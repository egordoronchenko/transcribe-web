# transcribe-web

Локальный веб-инструмент пакетной транскрибации видео и аудио через облачный Whisper (OpenRouter).

![transcribe-web UI](docs/screenshot.png)

Открываешь страницу на http://localhost:8080 → мышкой выбираешь папку с записями и папку для результатов → контейнер сам извлекает звук из видео (ffmpeg) и превращает его в текст, субтитры и JSON с таймкодами. Никакой GPU не нужен — распознавание идёт через API, оплата за минуты звука.

## Возможности

- **Два режима на выбор**: Whisper — дословная расшифровка с точными таймкодами и субтитрами; Gemini — расшифровка с разделением говорящих (`S1`, `S2`, `S3`) для совещаний и созвонов.
- **Любые форматы**: mp4, avi, mkv, mov, wmv, webm, flv, mpg и другие видео; mp3, wav, m4a, ogg, opus, flac и другое аудио. Звук извлекается автоматически.
- **Пакетная обработка**: выбор папки целиком (с подпапками) или отдельных файлов чекбоксами.
- **Живой прогресс**: файл, чанк, лог — через SSE. Страницу можно закрыть, задание продолжится на сервере.
- **Resume**: уже обработанные файлы пропускаются; флаг force для перезаписи.
- **Только сырой Whisper**: LLM-«полировка» сознательно не реализована — она портит доменную терминологию. Вместо неё — редактируемая подсказка распознавания (initial prompt) прямо на странице.
- **Надёжность**: длинные записи режутся на чанки и сшиваются обратно; ошибки API ретраятся с экспоненциальной паузой; файл без звука не роняет батч и не тратит деньги — пустая дорожка отсеивается до отправки в API.
- **Отчёт**: `job-report.json` со статусами, длительностями и временем работы по каждому файлу.
- **CLI-режим** тем же образом — для скриптов и автоматизации.

## Требования

- Docker Desktop (Windows / macOS) или Docker + Compose (Linux)
- API-ключ [OpenRouter](https://openrouter.ai/keys)

## Быстрый старт

```bash
git clone <repo-url>
cd transcribe-web
cp .env.example .env        # Windows: copy .env.example .env
# открой .env: впиши OPENROUTER_API_KEY и укажи HOST_ROOT
docker compose up -d --build
```

Открой в браузере **http://localhost:8080** (порт по умолчанию 8080, меняется
переменной `PORT` в `.env`) и дальше всё мышкой:

1. **Источник** — папка с видео/аудио. Появится список найденных файлов с чекбоксами (по умолчанию выбраны все).
2. **Выход** — папка для результатов.
3. **Режим** — Whisper или Gemini (см. ниже).
4. При желании поправь **подсказку распознавания** — термины, которые модель должна узнавать.
5. **Старт**. Прогресс, лог и статусы файлов обновляются вживую.

## Два режима

| | Whisper | Gemini |
| --- | --- | --- |
| Говорящие | нет | `S1`, `S2`, `S3` + описание каждого голоса |
| Таймкоды | точные | приблизительные, расхождение растёт к концу записи |
| Субтитры `.srt` | да | нет (таймкоды для них не годятся) |
| Цена | ~1× | ~2× |
| Скорость | быстрее (чанки идут параллельно) | медленнее (запись обрабатывается целиком) |
| Слабое место | на записях с плохим звуком теряет фрагменты и может выдумывать фразы на тишине | перефразирует формулировки |

**Whisper** — лекции, монологи, любой материал с чистым звуком, где нужны
дословность, субтитры и минимальная цена.

**Gemini** — совещания, созвоны, интервью: всё, где важно, кто и в какой
очерёдности говорил, а также проблемные записи, на которых Whisper теряет куски.
Подходит, когда расшифровка идёт дальше в суммаризацию.

Записи длиннее 30 минут в режиме Gemini режутся на части с перехлёстом в минуту.
Нумерация говорящих между частями может разойтись — в перехлёст попадают те же
голоса и модель получает описание уже найденных участников, но полной гарантии
это не даёт.

## Что получается на выходе

В выходной папке создаётся папка `transcripts`; в ней — подпапка на каждый файл
(структура подпапок источника сохраняется). Для файла `подпапка/лекция.avi`:

```
выход/
└── transcripts/
    ├── job-report.json         # сводка по всему заданию
    └── подпапка/
        └── лекция/
            ├── лекция.txt        # текст (в режиме Gemini — с метками [S1], [S2])
            ├── лекция.srt        # субтитры (только режим Whisper)
            ├── лекция.json       # сегменты с таймкодами + текст + параметры
            ├── лекция.meta.json  # время работы, модель, число чанков
            └── лекция.audio.mp3  # извлечённый звук (кэш; у mp3-источников не создаётся)
```

В режиме Gemini txt выглядит так — подряд идущие реплики одного человека
склеены в абзац:

```
[S1] Начну оперативное совещание с благодарности всем тем, кто эти две недели...

[S2] Одна из тем совещания — уборка муниципалитетов после зимы.
```

Расшифровка кто есть кто лежит в json в блоке `speakers`: по каждой метке —
описание голоса, роль в разговоре и имя, если оно звучало в записи.

Повторный запуск пропускает файлы, у которых txt+srt+json уже есть (resume).
Галка force перезаписывает.

## Настройки (.env)

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `HOST_ROOT` | `F:/` | Корень доступа: диск или папка, видимая в интерфейсе. Docker не умеет монтировать папки на лету, поэтому корень задаётся один раз — укажи достаточно широкий |
| `OPENROUTER_API_KEY` | — | Обязателен. На страницу никогда не выводится — только индикатор «найден / не найден» |
| `WHISPER_MODEL` | `openai/whisper-large-v3` | Любая whisper-совместимая модель провайдера (например `openai/whisper-large-v3-turbo` — быстрее и дешевле, но хуже с редкими терминами) |
| `GEMINI_MODEL` | `google/gemini-2.5-flash` | Модель для режима с говорящими. Нужны приём аудио на входе и structured outputs — подойдёт любая из линейки Gemini |
| `LANGUAGE` | `ru` | Код языка Whisper (`ru`, `en`, `de`, …) или `auto` — автоопределение |
| `PROMPT_FILE` | встроенный | Свой initial prompt по умолчанию: положи файл внутрь HOST_ROOT и укажи путь вида `/host/root/...` |
| `PORT` | `8080` | Порт веб-интерфейса |

Смена значений — правка `.env` + `docker compose up -d`. Пересборка образа не нужна.

Подсказку распознавания можно также править прямо на странице перед запуском:
текст действует только на текущее задание, пустое поле возвращает подсказку по
умолчанию, в API уходят первые 800 символов.

### Другие провайдеры (не только OpenRouter)

Инструмент работает с любым OpenAI-совместимым API транскрибации — достаточно
поменять три переменных в `.env`:

| Провайдер | `OPENAI_BASE_URL` | `WHISPER_MODEL` |
| --- | --- | --- |
| OpenRouter (default) | `https://openrouter.ai/api/v1` | `openai/whisper-large-v3` |
| [RouterAI](https://routerai.ru) | `https://routerai.ru/api/v1` | `openai/whisper-large-v3` |
| Groq напрямую | `https://api.groq.com/openai/v1` | `whisper-large-v3` |
| OpenAI | `https://api.openai.com/v1` | `whisper-1` |
| Локальный Whisper-сервер ([speaches](https://github.com/speaches-ai/speaches) и т.п.) | `http://host.docker.internal:8000/v1` | по настройке сервера |

Ключ кладётся в ту же переменную `OPENROUTER_API_KEY` (имя историческое — принимается
ключ любого провайдера). Требование к модели одно: поддержка
`response_format=verbose_json` с таймкодами сегментов — на них строятся srt и json.

OpenRouter и RouterAI проверены на реальном 35-минутном файле: скорость одинаковая
(~32 с на whisper-large-v3), но RouterAI отдаёт более крупные сегменты (~190 против
~260) — субтитры srt получаются длиннее и реже.
OpenRouter-специфичные настройки роутинга (предпочтение Groq) применяются только
когда база указывает на OpenRouter.

## CLI без веб-интерфейса

```bash
docker compose run --rm transcribe-web \
  python -m app.cli --in "/host/root/путь/к/видео" --out "/host/root/путь/к/выходу" \
  [--mode gemini] [--force]
```

Пути указываются внутри контейнера (`/host/root/...` = `HOST_ROOT` на хосте).
Ненулевой exit code, если хоть один файл упал.

## Как это работает

1. ffmpeg извлекает звук из видео → mono mp3 64 kbps (готовые mp3 идут как есть).
2. Уровень дорожки замеряется: если пик ниже −60 дБ, файл помечается как «нет звука» и в API не отправляется.
3. Дальше по режиму:
   - **Whisper**: звук режется на чанки по 600 секунд с перехлёстом 8 секунд (каждый гарантированно меньше лимита загрузки ~25 МБ), чанки уходят в `audio/transcriptions` параллельно по 3 с ретраями на 429/5xx, сегменты сшиваются по таймкодам, дубли из перехлёста отбрасываются.
   - **Gemini**: звук перекодируется в 32 kbps и уходит в `chat/completions` целиком (или частями по 30 минут с перехлёстом в минуту). Ответ приходит по JSON-схеме через structured outputs — это гарантирует валидную структуру даже когда в репликах встречаются кавычки. Дубли из перехлёста отбрасываются по совпадению текста, потому что времени от модели доверять нельзя.
4. Результат пишется по файлам: txt, json, meta (и srt в режиме Whisper).

## Безопасность

- API-ключ живёт только в `.env` (в `.gitignore` и `.dockerignore`), в образ не попадает, в логи не пишется.
- Контейнер видит только то, что смонтировано через `HOST_ROOT`; пишет только в выбранную выходную папку.
- Инструмент рассчитан на локальный запуск (localhost), аутентификации нет — не публикуй порт наружу.

## Ограничения

- Звук уходит в облако (OpenRouter и его провайдеры) — для конфиденциальных записей оцени применимость.
- Одно задание за раз (очередь простая по дизайну).
- Ключ и корень доступа задаются до старта контейнера, не через интерфейс.
